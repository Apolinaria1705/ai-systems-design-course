## Межа знань і правила розбивки на фрагменти (Stage B)

У ході аналізу канонічної колекції знань версії `course-seed-v1` (записи `R-A` та `R-B`) було порівняно два правила визначення межі фрагментації:
1. `fixed-72-v1`: фрагментація з обмеженням у 72 символи. Правило штучно розриває речення на частини (`F-A-72-1` – `F-A-72-4`), унаслідок чого жоден окремий фрагмент не зберігає повного зв'язку між ідентифікатором первинного запису, версією та точним текстовим уривком без необхідності реконструкції контексту з іншого фрагмента.
2. `sentence-pair-v1`: правило групування суміжних пар речень. Правило формує самодостатні одиниці пошуку `F-A` та `F-B`, повністю зберігаючи семантичну цілісність тверджень та первинні метадані походження.

Обрано конфігурацію `sentence-pair-v1`, оскільки вона детерміновано зберігає разом ідентифікатор первинного запису, його версію та точний діапазон підтвердного уривка, що є критично необхідним для виконання підстави судження про релевантність для випадків Evaluation Case A та Evaluation Case B. Одиниці пошуку зафіксовані як похідні артефакти (`derived retrieval-side artifact; not a canonical knowledge collection member`), а не як члени канонічної колекції знань.

## Порівняльний пошук та оцінювання результатів (Stage C2 & Stage C3)

Для двох тестових запитів виконано пошук за чотирма конфігураціями при $k=1$:
1. **Лексичний пошук (Lexical retrieval):** Для Case A повернув порожній список `[]` через лексичний пропуск (відсутність точного збігу ключових слів запиту з термінами фрагмента `F-A`). Для Case B повернув `[]`.
2. **Пошук на основі ембедингів (Embedding-based retrieval):** Для обох випадків повернув фрагмент `F-B` на першій позиції через високу семантичну подібність загальних слів запиту про квитанцію прогону, витіснивши цільовий фрагмент `F-A`.
3. **Гібридний пошук (Hybrid retrieval):** Повернув `F-B` на позиції rank 1.
4. **Лексичний пошук із переранжуванням ембедингами:** Через порожній первинний лексичний набір кандидатів створив порожній вихід `[]`.

### Судження про релевантність (Human Evaluation)
За оголошеною підставою судження про релевантність одиниця пошуку повинна пояснювати, які дані ідентифікують первинний запис, версію запису та точне місце підтвердного уривка (що міститься лише в `F-A`). Повернений фрагмент `F-B` є квитанцією прогону концепту і фіксує лише джерело та версію моделі, але не містить локалізації уривка доказів. Тому для всіх випадків повернення `F-B` оцінено як `not relevant`.

### Метрики інформаційного пошуку
- **Precision@1 (агрегований):** 0 relevant of 2 judged returned = 0.00 (для конфігурацій із порожнім виходом значення є `undefined` через нульовий знаменник).
- **Recall@1 (агрегований):** 0 of 2 reviewed relevant = 0.00 для всіх чотирьох конфігурацій. Жодна з конфігурацій при $k=1$ не змогла повернути шуканий фрагмент `F-A`.

## Операційні свідчення та обмежене рішення щодо конфігурації

Вимірювання операційних накладних витрат (за 3 прогони) зафіксувало:
- Лексичний пошук не потребує викликів локальної нейромережі, має мінімальну затримку та нульову вартість запиту за кодуваннями.
- Векторний та гібридний пошук вимагають ресурсомісткого кодування запиту через модель ембедингів та утримання ваг моделі в пам'яті процесу.

**Обмежене рішення щодо конфігурації:**
Оскільки жодна з досліджених конфігурацій не досягла ненульової повноти (recall@1 дорівнює 0 для всіх), впровадження моделі ембедингів на поточному етапі створює додаткові обчислювальні затримки та накладні витрати пам'яті без отримання будь-якої практичної переваги в якості видачі. На основі виміряних метрик та операційних свідчень зафіксовано збереження базової лексичної конфігурації (`lexical retrieval`) як обмежене інженерне рішення виключно для оголошених випадків зафіксованої межі `sentence-pair-v1` та $k=1$.
